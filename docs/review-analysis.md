# 轻量复盘（2026-10-18）

## 首要原则

简单、精简、克制。复盘只帮助用户连接“当时的理由”和“后来的感受”，不要求理解分析工具，不把回看变成任务。新增入口必须证明有助于记录或回忆。

## 当前页面

- 单一复盘视图，默认全部历史；仅提供全部、本周、本月三个时间范围。
- 默认已执行操作；未执行决定放在轻量下拉选择里，始终分开统计。待确认不进入分析。
- 用一行次数说明范围内有多少操作、多少已经回看，不显示计划执行率、纪律分或大指标卡。
- 理由按出现次数排列，默认前4种，可展开全部。每种理由直接显示非零感受次数，包含未回看与其他感受。
- 固定使用最近一次有效感受，不提供首次/最近切换，不生成值得保留/留意的建议卡，不展示感受变化分类、交叉分析或趋势图。
- 各理由使用等宽感受构成条，包含未回看与其他感受，并保留明确次数；用户不用自行换算比例。回看少于3次明确提示样本还少。
- 最多显示一条事实性的感受提示，优先展示同一理由下既满意也懊悔、且至少3次已知感受的分布。原样说明已回看分母与各感受次数，点开直接查看该理由的全部经历，沿用原有感受筛选和分页。不单独挑选两笔记录，也不评价理由好坏或从感受推断因果。没有足够回看时不生成提示。
- 点理由查看对应经历，点感受次数查看该理由下的对应感受。明细里通过一个下拉更换感受，不常驻一排筛选。
- 经历列表保留标的、动作、时间、主要理由、两行备注和最近感受；每页15笔。点开原记录查看完整备注、图片和所有回看。
- 从原记录返回仍保留明细弹层、已加载条目和筛选；弹层打开时隐藏底部导航。翻页失败保留已有内容，并支持重试。
- 页面底部仅保留原有的一条本周提醒，通过原生选择面板调整，与首页共享 current_focus。没有提醒时首页不增加空提醒任务。

## 统计与兼容

时间范围按 Asia/Shanghai 自然日解释。已执行操作按 executed_at（旧数据回退 occurred_at/created_at）归属周期；未执行决定按 recorded_at/created_at 归属周期。回看按 trade_event_id 关联，即使在另一个周期完成，也属于原来的操作。

每笔决定只计一次，使用查询时刻前最近的有效回看。无回看与无法识别的感受分开。仅有主观感受，不能推出收益、决策质量或行为改善。

服务端以 OPENID 隔离，完整分页读取已有操作与回看，任一页失败整体报错。旧版周月统计、首次口径、趋势和提醒版本接口保留兼容；当前页面不再暴露这些额外分析。已有原始数据、personal_rules 提醒版本和 user_config.review_reminder 不删除、不重写。

客户端缓存以范围、执行状态、页面修订号、上海日期和60秒有效期控制。汇总与明细均用请求序号防止过期结果覆盖新选择；页面卸载后忽略晚到结果。

## 历史读取修复

- 通用列表使用“排序字段 + _id”共同排序与定位，支持正序和倒序，同时间戳跨页不遗漏、不重复。查询归属不可由调用参数覆盖。
- 记录页按计划/临时决定筛选直接进入数据库查询，不能只在已加载的20条里过滤。切换类别独立重置游标并忽略旧请求；筛选无结果时仍保留切换入口，加载失败不显示成空分类。
- 单条记录的回看分页读取至完整，取消原先最多100次的隐藏截断。
- 满意等提示不再等同计划执行；保留三步记录，详情中的计划标签可以按实际情况更正，不增加必答问题，不批量改写旧标签。

## 验证

自动验证覆盖：三个范围与最近口径、全部理由展开、跨周期关联、未知/未回看、明细翻页与失败重试、原记录返回、缓存和过期响应、同时间戳双向分页、历史分类筛选、超过100次回看及提醒防重复提交。

模拟器验证使用既有记录，只读查看全部/周/月、理由明细、原记录和记录筛选，不提交测试交易、感受或提醒。初次精简阶段仅改客户端及查询方式；后续对照匹配改动涉及云函数，见下一节。全程无需迁移用户原始数据。

## 对照与后续想法补充（2026-10-18）

- 对照改为一次只读请求 `mode=comparison`，在当前范围、执行状态、理由的完整操作集合中寻找配对。优先同一标的且同一操作，其次仅同一标的，再次仅同一操作，最后才使用标的与操作均不同的两笔。市场和资产类型属于标的身份；沿用用户已确认的名称归并。每个情境选择最近的满意和懊悔决定，再优先两笔都更近期的情境，不仅检查首15条，也不按备注内容挑案例。
- 弹层明确标明同一标的/同一操作，以及无法匹配时的差别；这些是经历对照，不证明理由或操作造成感受。
- 已有操作备注标为“当时”；最近一次回看的备注、懊悔原因标为“后来”。没有的内容不补写，也不增加输入要求；最近感受已变为满意时，不混入更早的懊悔原因。
- 普通明细同样显示已有后续想法，长内容保留原记录入口。原始回看历史不修改。
- 对照依赖本次 tradeData 云函数更新；旧接口继续兼容，无需数据库迁移或新增集合。

## 取消两笔对照中间层（2026-10-18）

用户反馈两笔记录不能形成有意义的对比，且增加操作层级。复盘提示与理由列表统一进入该理由的全部经历，保留最近感受标签及“当时／后来”备注。移除客户端的配对状态、请求和说明文案；服务端已有 comparison 接口保留兼容，客户端不再调用，无需重新部署云函数。上节配对设计为历史方案，已由此调整取代。
