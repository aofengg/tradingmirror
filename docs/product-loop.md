# 交易留痕·产品级重构 Loop

## 目标

在不增加用户记录负担的前提下，将小程序从可用 MVP 提升到可正式发布的精致产品。工程完成度不低于“浮羽拾言”，同时保持交易行为工具应有的冷静、清晰和低刺激。

## 产品原则

1. 选择优先于输入；一次只问一件事。
2. 核心记录三步完成，不把复盘做成作业。
3. 评价行为是否遵循计划，不用事后股价证明当时对错。
4. 界面给用户平静感，不使用涨跌红绿、焦虑排行或过度激励。
5. 所有页面都要有加载、空、错误、成功和防重复操作状态。

## 固定验证场景

1. 首次打开：无任何记录。
2. 首页有一条操作前意图，待确认是否执行。
3. 首页有一条到期待回看操作。
4. 操作记录：标的 → 动作 → 主要原因 → 完成。
5. 记录列表同时包含“按计划”、“临时决定”、“待回看”和“已回看”。
6. 事后回看选择“懊悔”，继续选一个主要原因。
7. 周复盘同时有行为统计、重复模式和下周提醒。

## 七维评分（100 分）

| 维度 | 分值 | 通过标准 |
| --- | ---: | --- |
| 信息架构 | 15 | 首屏 3 秒内知道产品能做什么，主任务无竞争焦点 |
| 视觉系统 | 20 | 色彩、字号、间距、圆角、阴影和图标有统一 token，无临时字符图标 |
| 微文案 | 15 | 短、自然、无说教，每次只解释一个决策 |
| 交互效率 | 15 | 核心记录 3 步；常用标的一点即选；点击区不小于 80rpx |
| 状态完整性 | 15 | 加载/空/错误/成功/禁用/恢复草稿都有明确表达 |
| 性能与稳定性 | 10 | 无明显重复请求；无 console error；列表不额外全量读取快照 |
| 工程完成度 | 10 | 有通用组件、统一资产、结构测试和真实模拟器验证 |

发布门槛：总分不低于 90，任一维不低于该维度满分的 80%，核心流程阻断问题为 0。

## Loop 执行方式

1. Baseline：保存重构前截图、评分和问题清单。
2. System：先重构设计 token、图标和通用组件，禁止逐页随机美化。
3. Flow：按用户任务链重构，优先首页和三步记录。
4. Verify：每轮运行静态测试、真实编译、console 检查和固定场景截图。
5. Critique：对新截图重新评分，每轮只修复影响最大的 3–5 个问题。
6. Stop：达到发布门槛并连续两轮无核心回归时停止。

## 基线结论

当前版本信息架构 10/15、视觉系统 10/20、微文案 9/15、交互效率 12/15、状态完整性 9/15、性能与稳定性 6/10、工程完成度 5/10，合计 61/100。

核心差距：页面局部样式堆叠、品牌记忆弱、符号代替图标、空状态类似文档说明、列表请求有可删减的全量快照读取，且没有基于模拟器截图的评审闭环。
