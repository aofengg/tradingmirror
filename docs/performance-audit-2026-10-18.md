# 性能检查与优化（2026-10-18）

## 范围与结论

检查了 7 个页面的生命周期、页面跳转、列表和组件渲染、请求缓存、云函数查询、字段传输、数据库索引及图片处理。主要额外开销来自重复查询、隐藏列表提前读取、列表翻页重传已有数据，以及简单复盘继续返回旧版统计字段。

本次不增加产品页面或统计功能，不写入测试交易或回看。线上变更限于 tradeData 云函数及非唯一索引，客户端代码已在开发者工具编译验证，未上传或发布小程序新版本。

| 记录输入 | 每个字符同步写草稿 | 180 毫秒合并写入；离开立即保存最新输入，提交后不恢复旧草稿 |

只读缓存按账号、数据版本、日期及参数隔离，限制最多 80 项；失败结果不缓存，成功写入和下拉刷新清理缓存。明细缓存保留 Date 类型，并为每个消费者复制对象，避免互相修改缓存。

## 实测

2026-10-18，macOS 微信开发者工具、同一云环境、既有真实记录。旧兼容模式与 compact 模式各取 3 次，数值为请求耗时中位数和 UTF-8 JSON 响应体大小，不是弱网、冷启动或真实手机帧率测试。

| 复盘汇总 | 503 ms / 8,020 B | 421 ms / 3,210 B | 减少约 60% |

## 验证与边界

- 全部 34 个自动检查文件通过，包含原有功能回归和新增性能检查：缓存合并/失效/账号隔离，500 条列表增量渲染，121 次回看按页读取与失败重试，205 次历史完整性，以及定向查询的多页失败处理。
- 模拟器只读检查了首页、记录分类、待办、翻页、个股历史与概览、记录详情、相似决定、复盘全部/周/月、理由明细、我的和新记录入口。没有提交真实交易、感受、备注、归并或删除。
- 直接读取开发者工具控制台核对索引与组件告警；自动化日志接口未覆盖全部原生 Console 内容，因此以可见控制台为补充。开发工具在编译后立即自动导航时曾报 webview routeDone 系统错误，重新连接页面后正常导航和加载；此类工具时序错误不作为业务接口错误隐藏。
- 当前源码资源约数百 KB，已启用按需组件加载，未发现需要为现有体积引入分包的证据。图片已有压缩和大小限制，回看列表图片增加延迟加载。
- “全部数据”复盘和个股归组仍需按账号完整读取相应历史，复杂度会随历史增长；本轮通过投影、缓存、索引和定向明细减少开销，没有用截断历史换速度。数据达到数千/数万条时，应另行设计事务维护的汇总与归组索引，不以当前小样本速度代表无限增长后的性能。


## 第二轮交付复核

第二轮以数据完整性、异步请求和恢复能力为重点，补充以下修复；不增加产品页面或统计模块。

| 发现的边界 | 最终处理 |
| --- | --- |
| 待确认、待回看各超过 20 条时，记录页没有后续入口 | 分组保留游标并支持继续加载；单个分组和全部分组都可读完整历史；两组之一失败时不提交部分结果，保留旧列表与游标供重试 |
| 首页“换一条”只在最初 20 条待确认内循环 | 页末继续读下一批，最后一批再返回第一批；晚到响应与动画不会写入已卸载页面 |
| 已有内容的后台刷新没有显示全屏 loading，触底仍可能使用旧游标 | 记录列表、个股历史、回看历史使用独立的刷新状态，刷新中阻止翻页；刷新失败后解除状态并提供原有重试 |
| 首页读取中发生数据变更，重复进入仍等待旧请求 | 合并相同进行中读取；版本变化或强制刷新时排队重新读取，丢弃旧版本结果 |
| 首次联网失败后，后续页面重试仍复用失败的登录 Promise | 失败后释放请求，下次页面重试重新连接，并继续合并并发登录 |
| 数据迁移失败后，旧配置可能永久保留在缓存 | 不将迁移失败当作成功配置；释放缓存，允许下一次重新迁移 |
| 记录保存中退出、重开或新建草稿，旧请求晚返回 | 提交时固定实际发送的数据；草稿保存提交标识，相同提交在重开后仍复用标识；只清除属于本次提交的草稿；提交中禁止编辑步骤与清空草稿 |
| 交易确认或回看保存完成时页面已退出 | 成功结果仍使其他页面的数据失效，但停止向卸载页面渲染或弹提示 |
