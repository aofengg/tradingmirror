# 批量录入：1.8.0 实施规格

2026-11-05 用户确认开发，随后明确保留现有单条录入。当前实现与验收状态见 [1.8.0验收记录](batch-entry-1.8.0-acceptance.md)。此前清单式V1、自动提交V2及展开日期表单均已被本规格替代。

## 入口与范围

保留单条“标的 → 动作 → 原因”三步、点原因保存、单条草稿和完成页。今日页主标题右侧、记录页头部“＋”左侧提供一致的轻量“批量录入”入口，复用头部空间，不独占一行；保留单条第一步的原次级入口，首页两张单条主入口不变。新增独立页面 `pages/batch-record/index`，不搬移或覆盖单条草稿。操作前、已发生阶段各自保存批量草稿；前者固定现在，不允许倒填事前证据。

批量页支持多标的共用动作理由、连续录入不同操作及历史补记，不增加模式选择、导入文件、AI解析或批量附件。

## 同页任务链

1. 常驻股票名称／代码输入框，也可多选最近标的。手输一只可直接保存；多只用“添加”或键盘确认收成标签。标准化去重，无市场选择；不确定名称使用CUSTOM。
2. 选买入／加仓／减仓／清仓，再选主要原因。原因只选中，绝不提交。对象与动作在原因附近可见。
3. 显式点击“保存N条”。提交快照先落本地持久化队列；成功入队才清空本次标的、动作、原因、备注。日期保留，原页直接记下一笔，无成功页、继续按钮或复核清单。
4. 就近显示保存进度、已保存数量、重试与“撤销刚才N条”。“查看记录”原位展开，详细原记录才使用已有详情页。

一组内共用动作与原因，跨组相同标的允许独立事件，不合并真实多次操作；动作与原因不沿用上一笔。最多20条一次、40条待处理，达到上限保留当前输入并说明恢复路径。完成回执最多保留20组，未完成队列不清除。

## 日期与补充

日期只有一行：左“操作日期 可补记”，右“今天 ⌄”或历史日期。点击直接打开原生日期picker，选择即回填，没有展开表单或中间页面。选择、取消及换日期保留名称、标的、动作、原因与备注，不写云端。改日期仅影响尚未提交的输入，不重写已保存或在途快照。

具体时刻与备注收在“补充”；时刻可不填。只知道日期就保留日期精度，内部自然日零点只作分区锚点，不当真实成交时刻显示。历史补记的真实录入时间独立保存，列表与详情、统计、个股、状态图及AI读取保留其语义。日期上下文跨次录入保留；默认现在模式跨日更新为今天。

## 状态与恢复

批量草稿按账号、阶段隔离，与单条草稿独立。输入以短延迟写小草稿键，不重写或重绘整个回执历史。返回／退出保留未提交输入；显式重新填写需确认，只清当前草稿。

保存先生成稳定请求ID和不可变快照，前台每次3条执行；网络超时或未知结果用原ID、原快照重试。新一笔输入不被迟到响应覆盖，已确认成功不再次创建。页面离开后当前进程可继续，关闭小程序不承诺后台常驻；重开恢复持久化任务。

撤销绑定一次明确提交。云端事务移除未被后续回看或补充的事件，并保留无业务原文的技术墓碑；取消先于创建也不会复活。撤销中、撤销失败与保存结果不明均可辨认和重试。修改过的记录拒绝批量撤销，保留正常详情处理入口。

## 数据与权限

事件继续使用Schema v2，每条独立。新增 `occurred_date`、`occurred_at_precision`、`entry_source`；只为新记录写入，不重写旧事实。日期精度的待回看时间使用该自然日末加18小时；回看间隔跨桶时采用date_only，不产生虚假精确小时。AI识别补记来源，不把事后回忆当作当时留下的证据，不推断未知时刻的先后。

`tradeData.createBatchEntries` / `undoBatchEntries` 每次最多3条，每条事务同时处理事件与 `entry_requests` 技术回执。身份与请求ID共同生成确定ID，服务端校验归属、原因枚举和阶段。回执由服务身份所有，仅含不透明ID、带随机请求数的摘要、状态与版本，不包含真实用户身份、股票、备注或时间；客户端不写技术回执。详见 [数据库配置](database-setup.md)。

## 验证预算

常规无附件3条目标3秒内、20条目标8秒内，按实际环境和样本报告，不把一次耗时当稳定保证。保存超过1秒显示真实进行中状态。核验单条不回归、明确按钮边界、中文输入、去重、历史日期、跨周月、草稿恢复、换账号、失败重试、取消竞态、统计与AI语义、小常大屏及字体设置。实体设备与模拟器证据分别标明。
